# 2026.09.28 — Une clé effacée revenait au lancement suivant

## Signalement

La clé Claude, périmée, est effacée dans les Paramètres ; au relancement, elle réapparaît et
l'alerte « clé à corriger » revient.

## Cause

`ApiKeyStore.prefillDefaultsIfAbsent()` pré-remplissait **à chaque lancement** toute clé absente
depuis `dev-keys.properties` (build debug seulement ; la version publiée n'embarque aucune clé de
dev). Une clé effacée étant « absente », la valeur de dev revenait, et `KeyHealthMonitor` la
retrouvait inutilisable. Le moniteur lui-même était correct (il oublie le verdict d'une clé effacée).

## Correction

Marqueur `handled_<prefKey>` dans le stockage chiffré : posé dès qu'un fournisseur a eu une clé
(pré-remplie, saisie **ou effacée** via `setKey`). La valeur de dev n'est plus copiée qu'une fois,
jamais sur un fournisseur déjà pris en main. Décision isolée dans `shouldPrefill()` et testée
(`DevKeyPrefillTest`).

## Vérification

77 tests JVM, 0 échec. Pixel 7a (debug) : clé Claude effacée → application arrêtée et relancée →
plus d'alerte, plus de carte Claude dans les Paramètres.

À noter : `CLAUDE_API_KEY` reste dans `C:\DEV\PlantInfo\dev-keys.properties` (non modifié) ; elle ne
revient plus sur cet appareil, mais pré-remplirait encore une installation neuve.
