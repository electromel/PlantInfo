# 2026.07.10 — Validation manuelle d'une espèce + localisation depuis l'EXIF

## Demandes reçues

Sur une identification peu fiable (score < 60), l'utilisateur veut :
1. pouvoir **valider lui-même l'une des propositions alternatives** ;
2. **voir la localisation** de la photo importée (le géotag est présent dans le fichier mais n'était
   pas affiché).

Contexte technique : après un aller-retour de versions dû à l'auto-upgrade AGP d'Android Studio, le
projet tourne désormais sous AGP 8.13.2 / Gradle 8.13 / Kotlin 2.0.21 / KSP 2.0.21-1.0.28.

## Ce qui a été réalisé

### Localisation depuis l'EXIF (photos importées)
- `ImageStorage.readExifLocation(uri)` : lit latitude/longitude/altitude du géotag EXIF **avant**
  compression (celle-ci supprime l'EXIF).
- `CaptureViewModel.addPhotoFromUri` : pour une photo importée, le lieu inscrit dans la photo prime
  sur la position courante de l'appareil. La carte et la section « Lieu de la prise de vue »
  s'affichent donc pour les photos géotaguées, même sans GPS actif.

### Validation manuelle d'une hypothèse
- Room **v3** : colonne `userConfirmed` (migration `MIGRATION_2_3` non destructive — `ALTER TABLE …
  ADD COLUMN`, les données existantes sont conservées).
- `HistoryRepository.selectSpecies(entity, chosen)` : promeut l'hypothèse choisie en identification
  principale, renvoie l'ancienne espèce dans les alternatives, marque `userConfirmed = true`, efface
  les scores Pl@ntNet/IA (qui portaient sur l'ancienne espèce).
- `IdentificationContent` : chaque hypothèse porte un bouton « Choisir cette espèce » (callback
  `onSelectAlternative`, câblé dans Résultat **et** Détail). Une fois validée : pastille verte
  « Confirmé » à la place du score, bannière « validée manuellement », suppression des avertissements
  de faible confiance / divergence, masquage du détail des scores.
- La carte se recentre automatiquement sur la nouvelle espèce (GBIF re-interrogé via le nom
  scientifique, `MapViewModel` idempotent).
- L'**avertissement champignon reste systématique**, même après validation manuelle (§2.4).

## Correctif localisation EXIF (suite)

Le sélecteur de photos d'Android **masque le géotag à la source** (URI « picker » caviardée) : ni
`ACCESS_MEDIA_LOCATION` ni `setRequireOriginal` ne le débloquent dessus. Solution retenue :
- import via **le sélecteur de documents** (`OpenDocument`, `image/*`) ;
- permissions `ACCESS_MEDIA_LOCATION` + `READ_MEDIA_IMAGES` (cette dernière rend la première
  accordable) ;
- `ImageStorage.readExifLocation` essaie 3 candidats : Uri résolu média-document → recherche
  MediaStore par nom de fichier → Uri brut, chacun via `setRequireOriginal`.
- Distinction **import** (position EXIF uniquement, sinon aucune) vs **capture caméra** (position de
  l'appareil), pour ne plus afficher la position par défaut de l'émulateur sur une photo importée.

Vérifié sur émulateur : la localisation d'une photo géotaguée (Savièse) s'affiche correctement.
