# 2026.07.10 — Phase 3 : file d'attente hors-ligne + espèces protégées (Suisse)

## Demandes reçues

Poursuite du développement par phases : robustesse terrain (§3 du cahier des charges).

## Ce qui a été réalisé

### File d'attente hors-ligne + notifications (§3)
- `IdentificationWorker` (HiltWorker/CoroutineWorker) : rejoue l'identification via
  `IdentificationRepository.identifyAndSave`, sous contrainte réseau `CONNECTED`. Succès → notification ;
  échec réseau → `Result.retry()` (backoff exponentiel) ; échec définitif → notification d'échec.
- `IdentificationQueue` : sérialise la requête (chemins de photos déjà en stockage interne + GPS) dans
  un `Data` et enfile un `OneTimeWorkRequest` unique.
- `CaptureViewModel.identify` : sur un échec réseau (`queuedForRetry`), met en file au lieu d'échouer,
  affiche un message et réinitialise l'écran (les photos restent sur disque pour le worker).
- `NotificationHelper` : canal « Identifications », notification « Identification prête » (ou échec),
  ouverture de l'app au tap. Permission `POST_NOTIFICATIONS` demandée (Android 13+).
- WorkManager déjà initialisé via `Configuration.Provider` + `HiltWorkerFactory` (Phase 1).

### Alerte espèces protégées — liste Suisse (§2.4)
- `ProtectedSpeciesChecker` : liste **indicative** embarquée (toutes orchidées indigènes par genre +
  genres emblématiques largement protégés + quelques binômes). Croisement dans
  `IdentificationRepository.persist` : renforce `isProtected` sans jamais le désactiver.
- Prudence assumée (sur-signaler plutôt que manquer une espèce protégée) ; la bannière invite à
  vérifier la réglementation. Tests unitaires : `ProtectedSpeciesCheckerTest`.
