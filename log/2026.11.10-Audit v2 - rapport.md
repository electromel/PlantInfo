## 2. Cartographie

Architecture MVVM + Repository en couches `ui` / `data` / `domain` / `util` / `work`, injection Hilt.

| Zone | Rôle | Fichiers principaux |
|---|---|---|
| Pipeline d'identification | Pl@ntNet, puis IA avec repli, fusion des scores, persistance | `data/repo/IdentificationRepository.kt`, `data/remote/ai/AiOrchestrator.kt`, `domain/ConfidenceEngine.kt` |
| Clients distants | Un client par service, prompt et schéma communs | `data/remote/{plantnet,ai,gbif,web}` |
| Sécurité d'usage | Listes locales (toxiques, champignons, protégées), avertissement de confusion toxique | `domain/*Checker.kt`, `domain/model/Models.kt` |
| Clés API | Stockage chiffré, test, surveillance quotidienne | `data/keys/*` |
| Persistance | Room (2 tables, 10 migrations additives), photos JPEG en stockage interne | `data/db/*`, `util/ImageStorage.kt` |
| File hors ligne | WorkManager avec contrainte réseau, notification | `work/*`, `util/NotificationHelper.kt` |
| Interface | 3 onglets (Capture, Historique, Paramètres), écrans Résultat, Détail, Assistant | `ui/*`, fiche partagée `ui/result/IdentificationContent.kt` |

Parcours principaux : premier lancement (assistant), capture ou import puis identification, ajout par
nom, consultation de fiche (carte, questions à l'IA, photo complémentaire, validation manuelle d'une
hypothèse), historique (recherche, filtres, favoris, notes, suppression), partage et PDF, gestion des
clés.

Données personnelles : photos, coordonnées GPS, notes et historique restent sur l'appareil
(`allowBackup=false`). Sortent de l'appareil : photos et coordonnées (Pl@ntNet, fournisseur d'IA),
texte des questions (IA), nom d'espèce et zone de carte (GBIF, OpenStreetMap), nom saisi (Wikipédia).
